# GhostLink Cleanup Master Plan

Актуально: 17.03.2026
Режим: «хирургическая чистка без поломок»

## 1) Что это за файл
Это рабочий план чистки и стабилизации проекта.
Это **не skill** сам по себе, а операционный документ проекта.

Если захотим, позже можно сделать отдельный skill (`ghostlink-cleanup`) на базе этого плана.

---

## 2) Цель
- Привести код к аккуратной структуре.
- Убрать дубли, мусор и «патч-на-патче».
- Ничего не сломать в проде.
- Идти маленькими блоками с проверкой после каждого блока.

---

## 3) Принципы безопасности (обязательные)
1. Не трогаем сразу несколько критичных зон.
2. Один блок правок = одна проверка.
3. Для серверных файлов всегда делать бэкап перед правкой.
4. Не менять бизнес-логику и UI одновременно в одном блоке.
5. Любой рискованный рефактор только после фиксации текущего поведения.

## 7) Фазы хирургической чистки

## Фаза A (низкий риск, высокая польза) — Frontend JS
Файлы:
- `webapp-mini/app.js`
- `webapp-pwa/app.js`

Блоки:
1. Вынести повторяемые UI-хелперы в единый стиль функций.
2. Убрать дубли обработчиков/однотипных кусков.
3. Нормализовать обработку ошибок API (единый формат notify).
4. Стабилизировать логику экранов «Мои ключи» (без изменения бизнес-логики).

Проверка после каждого блока:
- ручная навигация: Home -> Мои ключи -> Добавить/Удалить/Обновить.
- проверка авторизации/логаута.

## Фаза B (низкий-средний риск) — PWA cache/update
Файлы:
- `webapp-pwa/sw.js`
- `webapp-pwa/manifest.json`

Блоки:
1. Исправить битую кодировку в `sw.js`.
2. Проверить стратегию кэша (network-first для html/js/css).
3. Прописать прозрачную версионность кэша.

Проверка:
- обновление PWA без «залипания» старого `app.js`.

## Фаза C (средний риск) — HTML/CSS выравнивание
Файлы:
- `webapp-mini/index.html`, `webapp-mini/styles.css`
- `webapp-pwa/index.html`, `webapp-pwa/styles.css`

Блоки:
1. Убрать разметочный мусор/дубли.
2. Подчистить классы и унифицировать секции.
3. Не менять визуальный язык, только порядок и читаемость.

## Фаза D (высокий риск) — API server
Файл:
- `api_server.py`

Блоки:
1. Карта модулей внутри файла (auth/proxy/devices/payments/admin).
2. Выделение безопасных утилит и нормализация имен.
3. Чистка дублей и dead-code.
4. Только потом возможная декомпозиция на модули (если нужно).

Обязательная защита:
- локальный backup перед каждым большим блоком.
- smoke-check ключевых endpoint’ов после правки.

## Фаза E (высокий риск) — Bot + `bot/*`
Файлы:
- `ghost_final.py`
- `bot/config.py`, `bot/security.py`, `bot/panel_api.py`, `bot/storage.py`

Блоки:
1. Исправить кодировку строк/логов.
2. Убрать дубли логики с API.
3. Привести к единым утилитам статусов пользователя и платежей.

## Фаза F — Доки/мусор/структура
Файлы:
- `AI_MAP.md`, `AI_RULES.md`, `AI_RECOVERY_PLAN.md`, `VPN_DIAGNOSTICS_LOG.md`, `.gitignore`

Блоки:
1. Привести docs к UTF-8 и актуальным разделам.
2. Перенести операционные документы в `docs/`.
3. Обновить `.gitignore` (db, pycache, локальные артефакты).
4. Перенести runtime-data в `data/` (на шаге 1 пользователь просил сделать позже).
