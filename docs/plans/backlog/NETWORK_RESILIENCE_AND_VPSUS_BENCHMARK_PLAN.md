# Network Resilience And VPSUS Benchmark Plan

## Статус

Backlog. Вернуться после наведения порядка в проектных документах и текущих P0/P1 задачах.

Обновлено: 16.06.2026.

## Цель

Понять, почему GhostLink VLESS плохо работает или не подключается на домашнем Wi-Fi, который выходит в интернет через LTE-роутер/MIMO/SIM, при этом на телефоне через мобильный интернет GhostLink работает нормально.

Отдельно сравнить с VPSUS/VPN Giant: их подписка тоже VLESS/TCP, но по наблюдению работает устойчивее в тех же условиях. Вытащить применимые технические идеи без копирования чужих секретов и без хранения чужой подписки в репозитории.

## Важное правило безопасности

1. Не коммитить и не вставлять в документы полный subscription URL, UUID, private key, shortId, SNI или другие рабочие параметры чужого VPN.
2. Для заметок использовать только редактированный вид:
   - домен подписки: `subs.eu-fffast.com`;
   - токен подписки: `[REDACTED]`;
   - серверные UUID/ключи/SNI: `[REDACTED]`.
3. Полную подписку анализировать только локально во временном файле вне Git или через буфер, затем удалить.

## Диагностическая гипотеза

Если GhostLink работает на мобильном интернете телефона, но не работает через домашний LTE-роутер, первичный подозреваемый не сервер, а сеть доступа:

1. MTU/фрагментация на LTE-роутере.
2. DPI/ограничения оператора для SIM в роутере.
3. DNS/IPv6/роутинг на домашнем роутере.
4. Порт/transport/fingerprint/SNI/Reality-параметры GhostLink менее устойчивы, чем у VPSUS.
5. Потери пакетов/джиттер/нестабильный uplink на домашнем LTE.

## План сравнения

### Этап A. Подтвердить границу проблемы

1. Телефон на мобильном интернете + GhostLink.
2. Телефон на домашнем Wi-Fi + GhostLink.
3. Mac на домашнем Wi-Fi + GhostLink.
4. Mac на другой сети + GhostLink.
5. Те же 4 проверки для VPSUS.

### Этап B. Сетевые тесты на домашнем Wi-Fi

1. DNS:
   - `dig link.112prd.ru`
   - `dig subs.eu-fffast.com`
2. TCP-порт:
   - `nc -vz <ghostlink_host> <ghostlink_port>`
   - `nc -vz <vpsus_host> <vpsus_port>`
3. MTU:
   - `ping -D -s 1472 1.1.1.1`
   - затем `1400`, `1360`, `1280`.
4. Потери/джиттер:
   - `ping 1.1.1.1`
   - при возможности `mtr`/`traceroute`.

### Этап C. Сравнить VLESS-параметры

Сравнивать только редактированные/обезличенные параметры:

1. Transport: TCP/WS/gRPC/etc.
2. Security: Reality/TLS/none.
3. Port.
4. Flow: например `xtls-rprx-vision`.
5. SNI/serverName.
6. fingerprint.
7. ALPN.
8. public host/CDN/fronting/география.
9. Наличие отдельных профилей `LTE AUTO` / `Самый быстрый AUTO`.

## Возможные решения для GhostLink

1. Добавить альтернативный VLESS endpoint под проблемные LTE-сети.
2. Проверить другой порт и SNI/fingerprint/Reality-настройки.
3. Добавить отдельный клиентский профиль `LTE AUTO`.
4. Добавить рекомендацию по MTU/клиенту, если проблема подтверждена как MTU.
5. Протестировать Hysteria2 как отдельный протокол из активного плана, не ломая рабочий VLESS.
6. Улучшить подписку `/s/<token>` так, чтобы она могла отдавать несколько профилей: основной + LTE fallback.

## Definition Of Done

1. Есть таблица сравнения GhostLink vs VPSUS по параметрам без секретов.
2. Есть результаты тестов на домашнем LTE/Wi-Fi.
3. Выбран один минимальный безопасный эксперимент для GhostLink.
4. Эксперимент проверен на:
   - домашнем LTE/Wi-Fi;
   - мобильном интернете телефона;
   - обычном Wi-Fi.
5. Решение внесено в runbook и, если нужно, в Mini App/бот-инструкции.
