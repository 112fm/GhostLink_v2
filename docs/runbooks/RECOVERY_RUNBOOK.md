# План аварийного восстановления GhostLink (чистый переезд)

## Цель
Быстро вернуть стабильную работу сервиса после критических сбоев и снизить риск повторного падения.

## Режим работ
- Окно работ: 2-4 часа.
- На время работ считаем прод нестабильным.
- Все изменения только по чеклисту ниже.

## P0. Перед сносом (обязательно)
1. Зафиксировать текущее состояние:
- Проверить доступ в панель хостера (VNC/Console).
- Сделать snapshot VPS (если доступно в панели).

2. Снять критичные бэкапы на сервере:
- `/root/ghostlink/.env`
- `/root/ghostlink/ghost_users.db`
- `/etc/x-ui/x-ui.db`
- systemd unit-файлы:
  - `/etc/systemd/system/ghostlink-api.service`
  - `/etc/systemd/system/ghostlink-bot.service`

3. Упаковать и выгрузить на ПК:
- Создать архив `ghostlink_export.tar.gz`.
- Скачать архив на локальный ПК.
- Проверить, что архив реально открывается и содержит файлы.

Стоп-чек P0:
- Если бэкап не проверен локально, к P1 не переходим.

## P1. Чистая переустановка VPS
1. Переустановить сервер в панели хостера (чистый образ).
2. Базовая настройка ОС:
- обновления пакетов
- установка `python`, `venv`, `git`, `sqlite`, `nginx` (если используется)
- установка `x-ui` (чистая)
3. Настроить SSH:
- вход по ключу
- keepalive
- отключение password-login после проверки ключа

Стоп-чек P1:
- SSH стабильно подключается из VS Code и не рвется в течение 10-15 минут.

## P2. Поднятие приложения
1. Развернуть код проекта в `/root/ghostlink`.
2. Восстановить только данные:
- `.env`
- `ghost_users.db`
- `x-ui.db` (только если нужна миграция текущих пользователей панели)
3. Проверить и запустить systemd сервисы:
- `ghostlink-api`
- `ghostlink-bot`
- `x-ui`

Стоп-чек P2:
- `/api/health` отвечает `{"ok":true}`.
- Все три сервиса `active (running)`.

## P3. Smoke-тест (до открытия пользователям)
1. Авторизация PWA/mini app.
2. Выдача нового ключа.
3. Подключение 1-2 тестовых клиентов.
4. Проверка трафика/онлайна в админке.
5. Открытие панели XUI через прокси-кнопку.

Стоп-чек P3:
- Нет ошибок `non existing outTag: WARP`.
- Нет циклических разлогинов в PWA.

## P4. Безопасность после запуска
1. Перевыпустить токены/секреты, которые светились:
- Telegram bot token (обязательно)
- при необходимости другие ключи в `.env`
2. Проверить Cloudflare/DNS:
- для Reality/VLESS запись должна быть DNS only (не Proxied).
3. Включить fail2ban и firewall с проверенными правилами.
4. Включить регулярные бэкапы БД.

## P5. Стабилизация после аварии
1. 24 часа мониторинга:
- `ghostlink-api`, `ghostlink-bot`, `x-ui`
- ошибки в `journalctl`
2. Только после стабилизации включать/менять WARP-маршрутизацию.
3. Любые изменения в роутинге только через precheck и бэкап.

## Откат (если что-то пошло не так)
1. Остановить сервисы API/бот.
2. Вернуть последний рабочий бэкап `.env` + `ghost_users.db` + `x-ui.db`.
3. Перезапустить сервисы.
4. Проверить `/api/health` и тестовый клиент.
