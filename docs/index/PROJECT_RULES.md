# PROJECT RULES

## 1) Git и безопасность

1. Не отправлять в публичный Git чувствительные файлы:
- `api_server.py`
- `ghost_final.py`
- любые `.db`
- приватные ключи/токены (`.env`, `pem`, `ssh keys`)
2. Перед push всегда проверять `git status` и staged-файлы вручную.
3. Для документации и фронтенда делать маленькие атомарные коммиты.

## 2) Правило активного плана

1. В `docs/plans/active/` должен быть только один рабочий план.
2. Новые инициативы сначала описываются в `docs/plans/backlog/`.
3. После смены приоритетов обязательно обновлять:
- `docs/index/PROJECT_CONTROL.md`
- `DOCS_INDEX.md`

## 3) Правило изменений прода

1. Сначала фиксируем проблему в плане.
2. Затем минимальный безопасный фикс.
3. Потом smoke-проверка на живом сценарии.
4. Только после этого переход к следующей задаче.

## 4) Правило mini-v2

1. `webapp-mini-v2` — единственный продовый фронтенд проекта.
2. Любые изменения UI/UX и API-интеграции вносятся только в `webapp-mini-v2`.
3. Каждый пользовательский сценарий проверяется отдельно smoke-проверкой до релиза.
4. Крупные изменения фронта выпускать только атомарными шагами.

## 5) Правило Bridge

1. Bridge (Shadow Bridge) — отдельный проектный поток.
2. До кодинга Bridge обязательна отдельная сессия согласования API, безопасности и UX.
3. Реализация Bridge допускается только после закрытия критичных P0 по текущему прод-потоку.

## 6) Диагностика и инциденты

1. При проблемах доступа/SSH использовать только runbook:
- `docs/runbooks/ACCESS_AND_INCIDENT_RUNBOOK.md`
2. Не выполнять рискованные «пакетные» команды без пошаговой проверки результата.

## 7) Strict Encoding (обязательно)

1. Весь проект (Frontend, Backend, Database, Configs) работает только в UTF-8.
2. Использование Windows-1251/ASCII и любых альтернативных кодировок запрещено.
3. Все новые файлы создаются в UTF-8 без BOM.
4. Любое появление некорректных символов (кракозябр) считается критическим багом.

### Backend JSON

1. Все JSON-ответы отдаются в UTF-8.
2. При сериализации обязательно использовать `ensure_ascii=False`.
3. `Content-Type` для JSON: `application/json; charset=utf-8`.

### HTML ответы

1. `Content-Type` для HTML: `text/html; charset=utf-8`.
2. В `<head>` первым meta-тегом должен быть `<meta charset="UTF-8">`.

### Database

1. Текущая база проекта: SQLite (UTF-8 по умолчанию).
2. Если используется DSN для MySQL/MariaDB, в строке подключения обязателен `charset=utf8mb4`.

### Деньги и символы

1. Символ валюты `₽` используется в явном виде.
2. Источник символа должен быть UTF-8-safe (код/конфиг в UTF-8).
